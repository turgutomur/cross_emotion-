\section{Experimental Setup}
\label{sec:setup}

\subsection{Hyperparameters}

We use DeBERTa-v3-base \citep{he2023deberta} as the encoder for all
main-table results, with a single linear head over the first-token
pooled representation. Training uses AdamW with linear warmup over the
first 10\% of steps followed by linear decay. The encoder learning
rate is $1{\times}10^{-5}$ and the head (and DANN/CDAN discriminator)
learning rate is $2{\times}10^{-5}$. Weight decay is $0.01$ on all
matrix parameters and zero on biases and LayerNorm. Effective batch
size is 32 across all cells (micro-batch 16 with two-step gradient
accumulation), sequence length 256, FP16 mixed precision. We train for
up to 15 epochs with early stopping (patience 3) on aggregate
validation macro-F1. Focal loss uses $\gamma=2$ and inverse-frequency
$\alpha$ normalized to unit mean per training split.

The DeBERTa-v3-large robustness run uses encoder learning rate
$5{\times}10^{-6}$ and head learning rate $1{\times}10^{-5}$, halved
from the base configuration to reflect the larger model's earlier
convergence; effective batch size, sequence length, focal
hyperparameters, and early-stopping criterion are unchanged.

All configurations are version-controlled in
\texttt{configs/default.yaml} and \texttt{configs/large.yaml}.

\subsection{Compute}

Main experiments run on Kaggle T4 and Google Colab L4 GPUs;
DeBERTa-large validation uses A100 80GB. Median wall-clock per seed:
$\approx 5$ minutes per epoch on L4 for the base configuration,
$\approx 7$--$8$ minutes per epoch on A100 for the large
configuration (after batch-size optimisation; see
Appendix~\ref{app:compute}). The full 6-method $\times$ 4-protocol
matrix at 3 seeds consumed approximately 60 GPU-hours of base-model
compute; the 5-seed large-model validation added $\sim$10 GPU-hours.

\subsection{Evaluation}

We report macro-F1 with classes restricted to those present in the
target evaluation split
($\texttt{evaluation.restrict\_to\_present}=\text{true}$). This is
the standard adjustment when the source training distribution
contains classes absent from the target (e.g. ISEAR has no
\emph{surprise} examples, so when ISEAR is the LODO target we evaluate
over five classes; otherwise we evaluate over all six). The same
adjustment is applied consistently across all six methods, so
within-protocol comparisons remain valid.

Bootstrap significance tests are run by
\texttt{scripts/run\_bootstrap.py} after all per-seed training runs
complete; details in Section~\ref{sec:methods:stats}.
